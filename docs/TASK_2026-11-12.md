## 1. Почта: настройки на уровне бизнеса

**Решение: Barowo шлёт письма с личного Gmail Ивана по SMTP. Resend для Barowo не используется.**

Причина: заменяя бота, нельзя менять адрес отправителя. Клиент отвечает туда же, куда отвечал
всегда, копия письма остаётся в «Отправленных» у Ивана, DNS настраивать не нужно.

Но установка мультибизнесная, поэтому один отправитель на всю систему не годится: в кабинет
клиента агентства нельзя положить пароль от почты Ивана, и письма клиента должны уходить с его
домена. Поэтому:

- Новая таблица настроек почты **на организацию**, с выбором транспорта:
  - `smtp` — хост, порт, пользователь, пароль, имя отправителя, адрес для ответов;
  - `resend` — ключ API и домен;
  - `none` — письма выключены (значение по умолчанию у нового бизнеса).
- Пароли и ключи — зашифрованы в базе, наружу не отдаются никогда (ни в HTML, ни в API,
  ни в логах). В форме редактирования показывать только «настроено / не настроено» и
  возможность ввести заново. Ключ шифрования — из переменной окружения.
- `lib/notify/email.ts` выбирает транспорт по организации, а не по глобальной переменной.
  `RESEND_API_KEY` в переменных остаётся запасным вариантом для системных писем.
- Экран `Ustawienia → Powiadomienia` (или отдельный `Ustawienia → Poczta`): форма настроек,
  кнопка «Отправить тестовое письмо» с показом реальной ошибки SMTP, если не удалось.
- Для SMTP использовать `nodemailer`. Параметры Gmail: `smtp.gmail.com`, порт 587, STARTTLS,
  логин — полный адрес, пароль — «пароль приложения» Google (не основной пароль).
- Ограничения Gmail, которые надо учесть в коде: 500 получателей в сутки у обычного аккаунта,
  не более 100 получателей в одном письме, вложения до 25 МБ. При ошибке квоты — понятное
  сообщение, а не «ошибка отправки».

Владелец проекта вводит адрес и пароль приложения сам, в переменных Railway или в форме.
**Никаких паролей в коде, в миграциях и в тестовых фикстурах.**

## 2. Отправка документов клиенту

Сейчас оферта и договор только скачиваются. В боте под готовой офертой была кнопка
**«📧 Wyślij tę ofertę klientowi»** (callback `offeremail_` в `lib/documents/barowo/legacy/Documents.gs`),
обработчик которой в выгрузку не попал. Точный текст письма из бота ещё выясняется.

Поэтому сделай так, чтобы текст не пришлось потом искать в коде:

- Кнопка «Wyślij klientowi» в карточке лида рядом с готовым документом.
- Перед отправкой — предпросмотр: кому, тема, текст, что приложено. Текст можно отредактировать
  в этом же окне перед отправкой.
- Шаблоны писем (оферта, договор) — в настройках бизнеса, с подстановками
  (`{klient}`, `{data}`, `{numer}`). Напиши разумный польский текст по умолчанию.
- Прикладывается PDF. DOCX — только если документ действительно нужен клиенту для правки.
- Факт отправки пишется в историю лида: когда, кому, кем, какой документ.
- Если почта у бизнеса не настроена — кнопка не активна и объясняет почему.

## 3. Три исправления

**3.1 Внутренние бизнесы не должны считаться клиентами агентства.**
`linkBusinessesToAgency` сейчас записывает каждый бизнес установки в `agency_clients`. Barowo —
собственный бизнес владельцев, а не платящий клиент. В связке с подпиской это превращает
перекладывание денег из своего кармана в свой же в «выручку агентства» и ломает раздел 10/25/65.

Нужно: признак «внутренний» у `agency_clients`. Внутренние не попадают ни в выручку месяца,
ни в раздел, ни в «ожидается/просрочено» — только в список обслуживаемых. Barowo пометить
внутренним при миграции. Тест: внутренний клиент с оплаченным заказом не меняет сводку.

**3.2 Устаревшая документация вводит в заблуждение.**
Записи 001–010 в `docs/decisions.md` описывают Supabase, Vercel и Google Cloud Run. Решение 017
их заменило, но они идут первыми, и новая сессия читает их сверху как действующие.

Нужно: пометить каждую отменённую запись строкой «ОТМЕНЕНО решением NNN» прямо в тексте, а в
начало файла добавить короткую сводку действующего стека: Next.js 16 + Postgres на Railway,
своя авторизация, без Supabase и без Google. Сами записи не удалять — это журнал.

**3.3 Экран `/agencja` не объясняет деньги.**
Владелец проекта говорит, что по экрану непонятно, откуда берутся суммы. Это главный дефект:
цифре, которую нельзя проверить глазами, не доверяют.

Нужно, чтобы без единого клика было видно: сколько пришло в этом месяце, от кого, и сколько из
этого лично моё. По каждому заказу — развёрнутая арифметика в одну строку: цена минус расходы =
база, дальше кому сколько и почему. Нераспределённое показывать явно, а не прятать.
Сначала сделай разметку на бумаге/в комментарии и покажи владельцу, потом верстай.

## 4. Telegram

Код есть, нужен токен бота в переменных Railway — владелец сделает сам. Твоя часть: проверить,
что подключение аккаунта, кнопки под уведомлением и ответ бота работают, и что при отсутствии
токена система не падает, а просто не шлёт.

## 5. Заморожено — не трогать

- **Stripe, модули, подписки.** Код оставить как есть, ничего не доделывать и не рефакторить.
  Первым клиентам CRM выдаётся бесплатно, счета выставляются вручную.
- **Правило 10% за приведение клиента.** Обсуждается, решения нет. Оставить как работает.
- **Возврат учёта часов.** Часы убраны намеренно: деньги делятся по ответственному за услугу.
  Не предлагать вернуть.
- **Редактор шаблонов договора.** Для Barowo хватает одного шаблона; для клиентов агентства
  документы настраиваются вручную при подключении.

## 6. Как работать

По одному пункту, не всё сразу. После каждого: `npm test`, `npm run build`,
`npx prettier --write .`, коммит, пуш, проверка логов деплоя на Railway.
Новое решение — запись в `docs/decisions.md`. Если видишь, что задача противоречит тому, что
уже в коде, — остановись и спроси, а не выбирай сам.
