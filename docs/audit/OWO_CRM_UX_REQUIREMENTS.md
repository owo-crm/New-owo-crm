# OWO CRM — требования к редизайну (UX Pilot)

> Основано на аудите текущего кода (2026-11-18) и решениях владельца из задания.
> Это **требования и ограничения**, а не новый дизайн. Разделено:
> **[Сохранить]** — функция есть и должна остаться; **[Решение владельца]** — зафиксировано в задании;
> **[Рекомендация]** — мнение аналитика, требует согласования.
> Существующий интерфейс — **не** образец.

## 1. Навигация

**[Решение владельца]**
- В новой версии **нет отдельных вкладок «Leady» и «Klienci»**. Функциональность лидов и
  клиентов **не удаляется**: её нужно разместить в других разделах.
- «Agencja» перерабатывается отдельно позже — сейчас только переносим как есть.
- «Usługi» — полностью новый каталог услуг.
- «Statystyka» — отдельный аналитический экран (сейчас спрятан в «Ustawienia»).

**[Сохранить]** Разделы и экраны, которые должны остаться доступными:
Pulpit, Umowy, Kalendarz, Poczta, Reklama, Agencja, Usługi, Zespół, Ustawienia (Firma, Szablony,
Źródła leadów, Powiadomienia, Import, Abonament, Poczta-ящик), Statystyka, карточка лида,
карточка клиента агентства, заказ агентства, генерация документов, переключатель бизнеса, поиск ⌘K.

**[Рекомендация] Куда «переезжают» Leady и Klienci** (варианты для обсуждения, не решение):
1. **Pulpit как рабочая очередь** — список обращений («ждут ответа», «мои», «на сегодня»)
   живёт на главной; карточка лида открывается поверх/рядом.
2. **Единый раздел «Zlecenia/Rozmowy»** с фильтрами по этапу: «Nowe zapytania» (бывшие Leady) →
   «W trakcie» → «Umowa wysłana» (бывшие Klienci) → «Podpisane» (Umowy).
3. **Umowy расширяется до «Klienci i umowy»**: человек → его обращения → договоры.
Выбор зависит от ответа на вопросы Q1–Q3 в [OPEN_QUESTIONS](OWO_CRM_OPEN_QUESTIONS.md).

**[Сохранить]** Видимость пунктов по модулю подписки и по виду кабинета (агентство / клиент)
и экран «Poproś o moduł» для выключенного модуля.

## 2. Карточка лида (самая важная форма)

**[Сохранить]** — всё, что есть сейчас:
- смена этапа (с проверкой версии и «Cofnij» 8 секунд), назначение ответственного;
- блоки: Kontakt, Wydarzenie, Oferta (пакет, бюджет), Dane do umowy, Wiadomość klienta,
  Dokumenty i płatności (документы, файлы, график платежей «змейкой» с отметкой оплаты);
- быстрые действия: Telefon, Czat (ссылка на переписку), E-mail z szablonu, Generuj
  Oferta/Umowa/Menu, Następny kontakt, Notatka;
- история с последним событием наверху;
- признак «ждёт ответа» и время ожидания; метка дубля со ссылкой;
- для агентства — переход в клиента агентства на этапе «Klient».

**[Решение владельца из предыдущих итераций]** вся работа с лидом — с одного экрана,
минимум вкладок; на компьютере «как можно больше на одном экране»; на телефоне быстрые действия
первыми, верхняя панель «назад / звонок / чат / e-mail»; без декоративных картинок.

## 4. Usługi — требования к будущему каталогу

**[Решение владельца]** каталог с карточками, описанием, категориями, иконками, ответственным
и несколькими исполнителями, ценами или индивидуальным ценообразованием, типом оплаты,
настройками, статусами.

**[Факт] ограничения текущей модели, которые придётся изменить (не в рамках дизайна):**
- у услуги **один** ответственный, он получает 100 % фонда 65 % (триггер в базе);
- цен у услуги **нет** (удалены решением владельца 12.11) — цена только в заказе;
- поле `description` есть в базе, но не выводится;
- категорий, иконок, нескольких исполнителей нет;
- встроенные услуги `crm` и `ads` защищены от удаления/переименования.

**[Рекомендация]** при проектировании карточки услуги явно показать: ответственный (кто
получает 65 %), исполнители, тип оплаты, связанные клиенты и заказы — чтобы финансовая
логика была видна из каталога. Противоречие «цены у услуги убрали ↔ в каталоге нужны цены» —
Q14.

## 5. Сквозные требования

- **[Сохранить]** Польский интерфейс, деньги в zł с грошами, даты по Варшаве.
- **[Сохранить]** Мультибизнес: переключатель, разное меню агентства и клиента, модули подписки.
- **[Сохранить]** Права: owner / admin / member; админ платформы; сервисный доступ агентства.
- **[Сохранить]** Живые обновления списков, PWA и push, светлая/тёмная тема.
- **[Сохранить]** Телефон — полноценная платформа (работа идёт в основном с телефона).
- **[Рекомендация]** Пустые состояния, ошибки синхронизации и «нет ключей» — явные (как сейчас
  в «Reklama»), не прятать.
