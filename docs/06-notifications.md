# 06 — Уведомления о новых лидах

Цель: **владелец узнаёт о заявке меньше чем за 5 секунд** и может ответить в 1–2 нажатия.

## Каналы

| Канал | Скорость | Плюсы | Минусы | Этап |
|---|---|---|---|---|
| **Telegram** | 1–2 c | уже привычен Barowo, кнопки действий, группы для команды | не у всех клиентов есть Telegram | MVP |
| **Web Push (PWA)** | 1–3 c | работает без сторонних приложений | на iPhone только после «Dodaj do ekranu głównego» (iOS 16.4+) | MVP |
| **E-mail** | 5–30 c | есть у всех | медленно, теряется | MVP |
| **SMS** (SMSAPI.pl) | 3–10 c | надёжнее всего | платно (~0,1–0,2 zł/шт) → только в плане Pro или с лимитом | этап 4 |

Пользователь выбирает каналы в «Ustawienia → Powiadomienia»; по умолчанию Telegram + Push + e-mail.

## Как отправляется (быстро и надёжно)

1. `ingest` записывает лид и сразу создаёт строки в `notification_deliveries`.
2. Edge Function `intake` в том же запросе (`EdgeRuntime.waitUntil`) отправляет все уведомления параллельно (не ждём cron).
3. Неудачные (`status = failed`) повторяет cron раз в минуту, до 5 попыток.
4. Тихие часы пользователя (`quiet_hours`) не касаются Telegram/Push по умолчанию — лиды важнее; можно включить.

## Содержание уведомления (польский)

```
🔔 Nowy lead · Wesele · 14.06.2027
Anna Nowak · +48 600 100 200
Gdańsk · 120 gości
Źródło: Meta Ads (kampania „Wesele 2027”)
⚠️ Termin zajęty   ← только если дата занята
„Dzień dobry, interesuje nas bar na wesele…”
```

Кнопки в Telegram: **✅ Skontaktowano** · **📄 Wyślij ofertę** (открывает веб-приложение на карточке) · **Otwórz w CRM**. Телефон в тексте кликабельный.
Push: заголовок «Nowy lead: Anna Nowak», текст «Wesele · 14.06.2027 · Gdańsk», клик → карточка лида.

## Подключение Telegram

- Пользователь нажимает «Połącz Telegram» → ссылка `t.me/<bot>?start=<link_token>` → бот привязывает `chat_id` к пользователю.
- Можно привязать группу команды (бот добавляется в группу, команда `/polacz <kod>`).
- Один бот на весь продукт (`@BarowoCrmBot` или подобный). Старый бот Barowo на Apps Script не трогаем до переключения (см. миграцию).

## Скорость реакции (speed-to-lead)

- `leads.first_response_at` ставится при первом действии: «Skontaktowano», звонок, письмо, оферта.
- Если лид не обработан за N минут (по умолчанию 15) — повторное напоминание; за 2 часа — напоминание владельцу/админу.
- На экране «Dzisiaj» — метрика «Średni czas reakcji» за 30 дней.

## Тесты

- формат сообщения (длинные имена, нет даты, нет телефона);
- ретраи и отсутствие дублей (идемпотентность по `lead_id + user_id + channel`);
- время от `POST /api/intake` до вызова Telegram API в e2e-тесте с моками < 2 c.

### Реализовано: Telegram (1.8, выключено)
`lib/notify/telegram.ts` — grammY, безопасный HTML-текст/кнопки и обработчики; `supabase/functions/telegram` — webhook с отдельным секретом. `createTelegramLink` создаёт ссылку `/start` на одноразовый код (10 минут). Сейчас поддерживается личный чат; групповые настройки относятся к будущей командной настройке. `/nowylead Imię | telefon lub e-mail | DD.MM.RRRR | miejscowość | rodzaj` создаёт лид общим конвейером, повтор update не дублируется. Кнопка контакта проверяет Telegram user и фирму. По умолчанию **все отправки выключены**: без `OUTBOUND_NOTIFICATIONS_ENABLED=true` функция отвечает 503; модуль тоже требует явного включения. Тесты вызывают исключительно мок транспорта. Нужны новый бот/username/секрет webhook, старый бот не затрагивается. Очередь уведомлений подключается в 1.11.

### Реализовано: PWA / Push (1.9, отправки выключены)
`/zainstaluj` (ссылка из настроек): инструкция iPhone/Safari и Android, кнопка согласия/подписки, отключение устройства. Manifest + Apple metadata + иконки 192/512, `sw.js` принимает push и открывает только внутреннюю карточку. Приватные страницы не кэшируются. Подписки доступны только самому участнику; sender использует VAPID на сервере, по умолчанию выключен, тесты — с моками. Нужны `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`; реальное разрешение/отправка не проверялись. iPhone — установленная PWA на iOS 16.4+ (сверено с локальным руководством Next.js).

### Реализовано: e-mail (1.10, выключено)
`lib/notify/email.ts` формирует польское текстовое/HTML уведомление участнику CRM (не клиенту лида), экранирует данные, не включает исходное сообщение. Resend `POST /emails` получает постоянный `Idempotency-Key=notification/<delivery_id>` для ретраев; HTTP-ошибки не считаются успехом, таймаут 5 секунд. По умолчанию отправка отключена, все тесты с внедрённым mock fetch. Нужны `RESEND_API_KEY` и подтверждённый адрес `NOTIFICATION_EMAIL_FROM`; домен/DNS в этой сессии не менялись. Сверено с официальным [Resend API](https://resend.com/docs/api-reference/emails/send-email).

### Реализовано: очередь/повторы (1.11)
Триггер leads пишет durable outbox в той же транзакции. Edge intake отправляет в waitUntil; Telegram-команда запускает фон по lead_id, ручной ввод — через Next after и защищённую notify-функцию. OUTBOUND_NOTIFICATIONS_ENABLED выключено по умолчанию. Секретов в клиентской сборке нет.

Notify защищена NOTIFICATION_CRON_SECRET. SQL для ежеминутного вызова — supabase/cron/notifications.sql; это ручной черновик, он не применялся, cron не зарегистрирован. URL/секрет берутся из Vault (crm_notification_url, crm_notification_secret), нужны pg_cron/pg_net. При выключенных отправках подготовка очереди и очистка 30-дневного intake_log доступна авторизованному cron.

15 минут — всем подписанным участникам; 2 часа — owner/admin. Перед отправкой проверяются фирма, членство, настройки, первый ответ и этап. После контакта/закрытия/отписки напоминание пропускается. Первые уведомления старше суток и напоминания по лидам старше недели не рассылаются при позднем включении. Неподключённые Telegram/Push не ставятся в очередь; истёкшие push-подписки удаляются. В одном worker письма идут с интервалом 600 ms, ошибки провайдера повторяются.

Проверено с моками: intake → Telegram API менее 2 секунд; SQL lease/retry/изоляция и отключение после ответа. Реальная скорость проверяется после отдельной настройки staging. Resend защищён постоянным idempotency-key, Push — tag; Telegram API не имеет ключа идемпотентности, поэтому при сбое после принятия сообщения API и до записи sent возможен редкий повтор.
