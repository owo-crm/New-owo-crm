## 1. Зачем

Сейчас документ (оферта, умова, меню) генерируется на отдельной странице, а отправить его клиенту
нужно вручную. Переписка с клиентом уже живёт в «Poczta → Wiadomości» (решение 051).
Цель — один путь: **кнопка в «Szybkie działania» → чат с клиентом с уже выбранным шаблоном →
проверить данные → «Wyślij» → клиент получает красивое письмо с PDF во вложении → этап лида
сдвигается сам.** Вся история (что отправили, что ответил клиент, статусы) — в одном чате.

## 4. Модель данных

### 4.1. Шаблоны = шаблоны почты с «действием»

Расширяем `public.mailing_templates` (не новая таблица — владелец просил хранить вместе):

| колонка | тип | смысл |
|---|---|---|
| `purpose` | text, `mail` \| `document` | `mail` — обычный шаблон рассылки/ответа; `document` — письмо с документом |
| `document_kind` | text, `offer` \| `contract` \| `menu` \| `file`, null | что прикладывать |
| `document_params` | jsonb, `{}` | параметры генератора, напр. `{"package":"simple"}` |
| `document_mode` | text, `quick` \| `form`, null | `quick` — данные правятся прямо в чате; `form` — сначала полная форма документа |
| `attachment_id` | uuid, null | для `document_kind='file'`: готовый PDF фирмы (прайс), из `document_files`/вложений |
| `quick_label` | text ≤ 40, null | подпись кнопки в «Szybkie działania»; null — кнопки нет |
| `quick_position` | smallint | порядок кнопок |
| `stage_after` | text, null | ключ этапа, на который сдвинуть лид после отправки (только вперёд) |

RLS — как у `mailing_templates` сейчас (члены читают; правят owner/admin). Шаблоны с
`purpose='document'` в рассылке («Rozsyłki») **не показываются** — у них нет смысла без лида.

### 4.2. Связь письма с документом

- `mail_messages.attachments` (уже есть, jsonb) для исходящих пишем
  `[{ "documentId": "...", "fileId": "...", "filename": "Oferta_Standard_BAROWO_0123.pdf" }]`.
- `documents.status` → `sent`, `documents.sent_at` → время отправки (колонки уже есть).
- В чате вложение — ссылка на скачивание через существующий маршрут `/api/documents/[fileId]`
  (проверка прав там уже есть).

### 4.3. Движок документов кабинета

`organizations.document_engine` уже есть (`barowo` / null). Правило:
- `barowo` → PDF генерируется (`generateOffer`, `generateContract`, `generateGuestMenu`).
- нет движка → доступны только шаблоны с `document_kind='file'` (готовый PDF) и `mail`.
- Новые движки для других отраслей — позже, отдельным решением; интерфейс один:
  `engine.defaults(lead, params)` → поля формы; `engine.render(values)` → `{ pdf, filename, snapshot }`.

## 5. Поток для пользователя

### 5.1. Быстрая оферта (Simple / Standard / Premium)

1. Карточка лида → «Szybkie działania» → **«Oferta Simple»**.
2. Открывается `/poczta?c=<email>&tpl=<templateId>&lead=<leadId>`.
3. В поле ответа выбран шаблон, над ним — **карточка документа**:
   дата, место, гости, часы, цена (подсказка по каталогу и числу гостей; из карточки лида),
   кнопка «Podgląd PDF». Поля можно поправить.
4. «Wyślij» → сервер: проверка → генерация PDF с этими данными → запись в `documents`
   (снимок, номер) → письмо по шаблону + PDF вложением → `mail_messages` (исходящее,
   с вложением и id Resend) → `documents.status='sent'` → этап лида вперёд → событие в истории лида.
5. Если что-то упало после генерации, но до отправки — документ остаётся `generated`,
   письмо не считается отправленным, пользователь видит ошибку и может нажать ещё раз
   (новый документ не плодится: переиспользуем последний `generated` с теми же данными).

### 5.2. Oferta personalna и Umowa (через полную форму)

1. Кнопка → существующая форма (`/leady/[id]/oferta?pakiet=...&personal=1`, `/leady/[id]/umowa`).
   - Personalna: выбор пакета (Simple/Standard/Premium) **в форме**, меню/алкоголь/добавки
     редактируются; гости и цена за час — из карточки лида.
2. «Generuj» → документ создаётся как сейчас → **редирект в чат**
   `/poczta?c=<email>&tpl=<templateId>&doc=<documentId>`.
3. В чате шаблон выбран, PDF уже прикреплён (видно имя файла), «Wyślij» отправляет.

### 5.3. Нет e-mail у клиента

Кнопки документов активны, но в чате вместо поля ответа — поле «E-mail klienta» с сохранением
в карточку лида. Без адреса отправка невозможна; генерация (скачать PDF) — возможна.

### 5.4. Этап после отправки

`stage_after` из шаблона; применяется, **только если** этап есть в воронке кабинета и стоит
**дальше** текущего (`pipeline_stages.position`). Лиды на этапах `won`/`lost` не трогаем.
Barowo: оферта → `offer_sent`, умова → `contract_sent`, меню — без смены.

## 9. Этапы работы (по порядку, каждый — отдельный PR)

1. **Карточка лида:** вернуть выбор Simple/Standard/Premium (временно три кнопки на форму),

   «Rozsyłki» скрывает `purpose='document'`, в «Ustawienia → Poczta → Szablony» их можно править.
3. **Отправка письма с PDF из чата:** вложения в `sendReplyAction`, запись в `mail_messages`,
   `documents.status='sent'`, сдвиг этапа, событие в истории лида; показ вложения в чате.
4. **Быстрые оферты в чате:** карточка документа в поле ответа, `?tpl=&lead=`, «Podgląd PDF».
5. **Personalna / Umowa / Menu:** форма → редирект в чат с `doc=`.
6. **Кнопки «Szybkie działania» из шаблонов** (вместо жёстких), нет e-mail → ввод адреса.
7. **Импорт шаблонов для других кабинетов** (`scripts/templates-import.ts`) + инструкция.

Каждый этап: тесты базы (RLS: чужая фирма не видит/не отправляет шаблон и документ),
unit (сдвиг этапа только вперёд; повтор не создаёт второй документ), e2e со скриншотами
(компьютер и телефон), запись в `PROGRESS.md` и решение 053 в `docs/decisions.md`.

## 10. Ограничения и риски

- Вложение увеличивает письмо (PDF Barowo ≈ 0,3–1,5 МБ) — в пределах Resend (40 МБ) и Gmail (25 МБ).
- Через SMTP вложения тоже уходят, но без статусов (решение 052).
- Генерация PDF (LibreOffice для умовы) занимает секунды — кнопка «Wyślij» показывает прогресс,
  повторное нажатие заблокировано.
- `next_contact_at` перестаёт задаваться из интерфейса — напоминания «следующий контакт» тоже
  перестанут появляться для новых лидов. Владелец согласен (пункт 8); если нужно вернуть —
  отдельной задачей.
