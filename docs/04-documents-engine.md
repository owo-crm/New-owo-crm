# 04 — Движок документов (договоры и оферты)

Это **главная фишка продукта**. Качество здесь важнее всего остального.

## Идея: одна модель — много дизайнов

```
Данные лида + фирмы + форма пользователя
            │
            ▼
   DocumentContent (JSON, без оформления)
            │
   ┌────────┼─────────────┐
   ▼        ▼             ▼
 Дизайн A  Дизайн B     Дизайн C        ← каждый дизайн = React-компонент + стиль для Word
   │
   ├─► HTML (предпросмотр в браузере, онлайн-оферта)
   ├─► PDF  (Chromium печатает тот же HTML → шрифты и вёрстка 1:1)
   └─► DOCX (библиотека docx по той же модели)
```

Текст договора не зависит от дизайна. Пользователь может переключить дизайн и получить тот же договор в другом оформлении без повторного ввода.

## DocumentContent (TypeScript)

```ts
type DocumentContent = {
  kind: 'contract' | 'offer';
  number: string;            // UM/2026/014, OF/2026/031
  issuedAt: string;          // ISO date
  city: string;
  seller: Party;             // из organizations
  client: Party;             // из лида + форма
  event: { type?: string; date?: string; venue?: string; city?: string; guests?: number; hours?: string };
  sections: Section[];       // текст
  pricing?: { lines: PriceLine[]; totalGrosze: number; beforeDiscountGrosze?: number; deposits?: Deposit[] };
  media?: { coverPath?: string; gallery?: string[] }; // для оферт
  note?: string;             // личное сообщение клиенту (только оферта)
};
type Section = { title?: string; blocks: Block[] };
type Block =
  | { t: 'p'; text: string }               // текст с переменными {{client.name}}
  | { t: 'list'; items: string[]; ordered?: boolean }
  | { t: 'clause'; no: string; text: string } // § 1, § 2 ...
  | { t: 'priceTable' }
  | { t: 'signatures' }
  | { t: 'pageBreak' };
```

## Переменные

- Формат `{{client.name}}`, `{{event.date}}`, `{{pricing.total}}`, `{{deposits[0].amount}}`.
- Список всех переменных — `lib/documents/variables.ts` с польскими подписями («Imię i nazwisko klienta»).
- Перед генерацией: если переменная пустая — документ **не создаётся**, в предпросмотре поле подсвечено, пользователь заполняет его в форме справа.
- Суммы прописью по-польски («dwa tysiące pięćset złotych») — функция в `lib/documents/pl-amount.ts` с тестами.

## Договоры — 3 дизайна (минимум)

| id | Название (PL) | Описание |
|---|---|---|
| `contract-classic` | Klasyczny | формальный, засечковый шрифт, § по центру, как у нотариуса |
| `contract-modern` | Nowoczesny | гротеск, цвет фирмы в шапке и номерах §, логотип |
| `contract-minimal` | Minimalistyczny | много воздуха, тонкие линии, мелкий логотип |

Во всех: шапка со сторонами, пронумерованные §, таблица оплаты (задаток, остаток, сроки), блок подписей, номер страницы «Strona 1 z 3» в PDF.

### «Договоры такие, как у клиентов»

Каждая фирма хочет **свой** текст договора. Путь онбординга:

1. Пользователь загружает свой договор (DOCX/PDF) или вставляет текст.
2. Сервер достаёт текст (`mammoth` для DOCX, `pdf-parse` для PDF).
3. **ИИ-помощник** (Claude API) раскладывает текст на §-блоки и предлагает переменные: «Jan Kowalski» → `{{client.name}}`, «15.06.2027» → `{{event.date}}`, «500 zł» → `{{deposits[0].amount}}`.
4. Пользователь проверяет в редакторе: слева текст, переменные выделены цветными «пилюлями», кнопка «+ Wstaw pole».
5. Сохраняется как `document_templates` фирмы. Можно иметь несколько шаблонов (свадьба / корпоратив).

Без ИИ (если нет ключа) — тот же редактор, переменные расставляются вручную.
Готовые системные шаблоны договоров — по одному на отраслевой пресет (на основе договора Barowo, без данных Barowo).

> Юридическое предупреждение в интерфейсе: «Szablon nie jest poradą prawną. Za treść umowy odpowiada firma.»

## Оферты — 3 стиля (минимум)

| id | Название (PL) | Описание |
|---|---|---|
| `offer-premium-dark` | Premium | тёмный фон, большое фото на обложке, акцентный цвет — в духе Barowo |
| `offer-elegant-light` | Elegancki | светлый, свадебный, мягкие цвета, галерея 3 фото |
| `offer-compact` | Konkretny | 1 страница: пакет, что входит, цена, кнопка/контакт — для быстрых ответов |

Состав оферты: обложка (лого, имя клиента, дата мероприятия) → личное сообщение → пакет и что входит → опции → цена (с ценой до скидки, если указана) → условия (задаток, срок действия оферты) → контакты и CTA.

Каналы отправки оферты:
- PDF + DOCX для скачивания;
- **онлайн-оферта** `app.barowo.com/o/<token>` — красивая страница, кнопка **«Akceptuję ofertę»** → лид переходит в стадию «Oferta zaakceptowana», владелец получает уведомление; фиксируем просмотры (`offer_viewed`);
- письмо через Resend с предпросмотром и отправкой только по кнопке ✅ (правило из бота v39).

## Брендинг фирмы

Все дизайны берут из `organizations`: логотип, `brand_color`, шрифты (`brand_fonts`: заголовки/текст), реквизиты. Свои шрифты фирма загружает (woff2/ttf) — нужна галочка «mam licencję na ten font».

Для Barowo: перенести существующий дизайн оферты (шрифты Lozung Caps, Rimma_sans Bold, Kenyan Coffee Bold — см. `crm-system/apps-script/README.md`) как настройки бренда Barowo поверх стиля `offer-premium-dark`. Серифный вариант Barowo был отклонён — не использовать.

## Шрифты в PDF и Word

- PDF: шрифты подключаются через `@font-face` (файлы из Storage), Chromium встраивает их в PDF. Проверка: `pdffonts` в тесте.
- DOCX: библиотека `docx` умеет встраивать TTF (`fonts` в `Document`). Если шрифт не встроился — fallback на Arial/Georgia, Word остаётся редактируемым.

## Нумерация и версии

- Номер выдаётся атомарно (`document_counters`, `for update`), формат настраивается: `UM/{YYYY}/{NNN}`.
- Повторная генерация = новая версия, старые файлы не удаляются. В карточке — «Dokumenty»: последние версии, PDF, Word, статус.

## Тесты движка (обязательные)

- рендер каждого дизайна на фикстуре с длинными именами, польскими буквами (ąęłńóśźż), эмодзи (баг v39!) — без падений;
- пустая переменная блокирует генерацию;
- сумма прописью;
- PDF: число страниц > 0, шрифты встроены; DOCX открывается (`mammoth` читает текст обратно);
- снапшот-тесты HTML каждого дизайна.
