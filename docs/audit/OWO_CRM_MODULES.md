## 1. Pulpit — главная панель

**Файлы:** `app/(app)/dzisiaj/page.tsx`, `lib/leads/dashboard.ts` (`work_queue`),
`lib/leads/charts.ts` (`dashboard_charts`), миграции `0017`, `0029`.

**Назначение.** «Что требует моего внимания сейчас» + картина сезона одним взглядом.

**Данные и блоки [Факт]:**

| Блок | Что показывает | Правило расчёта |
|---|---|---|
| KPI «Bez odpowiedzi» | лиды без первого ответа | этап `kind='open'`, `first_response_at is null`; импорт из бота на этапе выше «new» считается отвеченным. Красный, если > 0 |
| KPI «Zapytania w tym miesiącu» | лиды, созданные с 1-го числа (Варшава) | `created_at ≥ начало месяца` |
| KPI «Zamknięte w tym miesiącu» | лиды на этапе `won`, изменённые в этом месяце | `kind='won' and updated_at ≥ начало месяца` — **[Предположение]** считает и лиды, подписанные раньше, но отредактированные в этом месяце |
| «Zapytania miesiąc po miesiącu» | 6 последних месяцев, столбики «Z podpisaną umową» / «Bez umowy» | по `created_at`; «с договором» = текущий этап `won` |
| «Najbliższe wydarzenia» | 6 ближайших мероприятий | `event_date ≥ сегодня`, этап не `lost`; бейдж «Umowa podpisana» (`won`) / «Wstępnie» (`open`); ссылка «Kalendarz», если модуль включён |
| «Obłożenie najbliższych miesięcy» | 6 месяцев вперёд: «Potwierdzone» / «Wstępne» | по `event_date`; `won` vs `open` |
| «Skąd przychodzą (90 dni)» | топ-5 источников + «Inne» | по `source_label` лида за 90 дней |
| «Zacznij tutaj» (начальная настройка) | 3 ссылки: подключить форму, пригласить команду, импорт | виден, пока нет подключённого канала формы (`form_connected`) |

**Действия:** переход в лид, в календарь, в настройки; на телефоне — «Dodaj lead».
Живое обновление (`LiveUpdates`).

**Не используются на экране, хотя считаются в `work_queue` [Факт]:** очередь `waiting`
(10 старейших), `tasks` (звонки на сегодня по `next_contact_at` и `lead_tasks`), `mine_count`,
`response_minutes` (средний ответ за 30 дней). Тексты для них в `pl.json` есть («Kolejka», «Na dziś»).

**Входящие данные:** лиды, этапы воронки, каналы. **Используют данные:** никто (только отображение).

**Пробелы:** нет денег (выручки) на Pulpit; нет фильтра по ответственному; метрика «Zamknięte»
зависит от `updated_at` — см. открытые вопросы.

## 2. Leady — лиды и карточка лида

**Файлы:** `app/(app)/leady/page.tsx`, `app/(app)/leady/[id]/page.tsx`,
`components/leads/*` (`lead-editor`, `lead-rail`, `lead-row`, `lead-filters`, `kanban`),
`lib/leads/*`, миграции `0002–0006`, `0013`, `0015`, `0038`.

**Назначение.** Приём и обработка обращений клиентов от первой заявки до подписанного договора.

### 2.1 Список «Leady» [Факт]
- Заголовок со счётчиком; поиск по имени/телефону/e-mail (по мере ввода, `search_leads`).
- Чипы: «Wszystkie N», чипы этапов с количеством, быстрые фильтры «Czekają na odpowiedź»,
  «Moje», «Ten miesiąc», отдельные пунктирные чипы проигрышных этапов (Odrzucony, Spam).
- «Filtry» (скрытая форма): этап, источник (канал), ответственный / «nieprzypisany», даты от–до.
- Сортировка: сначала ждущие ответа, затем новые. Пагинация по 50.
- Проигрышные этапы (`lost`) по умолчанию скрыты.
- Карточка списка: имя, этап, «тип · дата события», «сколько прошло», город, стрелка;
  ждущие ответа — красная полоса.
- Вкладки «Lista · Kalendarz» (если модуль календаря). Вид «Etapy» (канбан `view=board`,
  `components/leads/kanban.tsx`) — код есть, вкладка убрана (решение 047).

### 2.2 Карточка лида `/leady/[id]` [Факт] (решения 048–049)
- Слева колонка последних 50 лидов (мгновенный поиск, «Wszystkie / Nowe»).
- Шапка: имя, пилюля этапа (смена этапа), №, источник, «Ostatnia aktywność».
- «Холст» блоков, каждый правится целиком карандашом:
  - **Kontakt** — `client_name`, `phone_e164`, `email`;
  - **Wydarzenie** — `event_type`, `event_date`, `event_city`, `venue`, `guests`, `service_hours`;
  - **Dokumenty i płatności** — последние документы (PDF/Word), файлы («Galeria» — фото,
    «Plik» — документ, до 10 МБ, `lead_attachments`), платежи «змейкой»;
  - **Oferta** — `package_name`, `budget_grosze`;
  - **Dane do umowy** — `client_full_name`, `client_address`;
  - **Wiadomość klienta** — `message`.
- **Szybkie działania:** этап; «Oznacz jako skontaktowany» (только на этапе `new` без ответа);
  Telefon (`tel:`); **Czat** (ссылка `chat_url`, при первом нажатии — ввод ссылки WhatsApp/
  Messenger/Instagram); «E-mail z szablonu» (`/poczta?lead=`); «Generuj: Oferta / Umowa / Menu»
  (модуль `documents` + генератор Barowo); «Następny kontakt» (`next_contact_at`, Варшава);
  «Przypisany do» (кнопки участников); «Notatka».
- «Historia aktywności»: 3 последних события + «Pokaż wszystkie» (до 200).
- После правки — плашка «Zapisano / Cofnij» (8 секунд, `undo_lead_change`).
- Кабинет агентства: на этапе «Klient» — карточка «Dodaj klienta agencji / Otwórz klienta agencji»
  (`components/agency/lead-client-card.tsx`).

### 2.3 Создание лида [Факт]
- `/leady/nowy` — ручная форма (`lib/leads/manual.ts`, канал `manual`).
- Кабинет агентства: `/agencja/leady/nowy` — мастер 4 шагов (фирма и контакт; кто привёл;
  интересующие услуги; рекламный бюджет и заметка) → `agency_lead_details`, `agency_lead_services`.
- Внешние каналы — см. раздел 13 и «Źródła leadów».

### 2.4 Статусы — этапы воронки [Факт]
Этапы хранятся per-бизнес (`pipeline_stages`: key, label, position, kind `open|won|lost`).

| Пресет | Этапы |
|---|---|
| `event-services` (Barowo, `0015`) | Nowy → Skontaktowano → Oferta wysłana → Oferta zaakceptowana → Umowa wysłana → **Umowa podpisana (won)** → **Zadatek wpłacony (won)**; проигрыш: Odrzucony, Spam |
| `agency` (OWO Ads) | Nowy → Kontakt → Spotkanie → Oferta → **Klient (won)**; Odrzucony, Spam |

**[Факт]** Экрана для редактирования этапов нет (только SQL). Таблица `custom_field_defs`
(свои поля) и `lead_tasks` (задачи) есть в базе, интерфейса для них нет.

### 2.5 Бизнес-правила [Факт]
- Перевод с `new` на любой неп­роигрышный этап ставит `first_response_at` (метрика ответа).
- Правка через `change_lead` с проверкой версии (`updated_at`) — защита от одновременной правки.
- Дубли: при приёме ищется лид с тем же телефоном/e-mail за 30 дней → событие `possible_duplicate`
  в обоих лидах (ссылка «Otwórz duplikat»).
- Генерация **договора** двигает этап вперёд до `contract_sent`, но никогда назад
  (`stageForward`, `lib/documents/service.ts`). Генерация оферты и меню этап **не** меняет.
- Удаление — мягкое (`deleted_at`).

**Используют данные лида:** Pulpit, Klienci, Umowy, Kalendarz, Poczta, Statystyka, Reklama
(через `utm_campaign`), уведомления, документы, платежи.

**Пробелы:** нет экрана настройки воронки и своих полей; нет задач; нет массовых действий;
нет «Spam / Usuń lead» в карточке (есть в Telegram-боте Barowo); канбан скрыт.

## 3. Klienci — клиенты (вне меню)

**Файлы:** `app/(app)/klienci/page.tsx`, `lib/leads/people.ts`, `clients_list` (`0030`).

**Назначение [Факт]:** список людей, которым уже выслан договор, — по строке на человека
(склейка по телефону, иначе по e-mail в нижнем регистре).

- Попадает: этап с позицией ≥ «Umowa wysłana» (`client_stage_position`), не `lost`.
- Колонки: имя, контакт, самый дальний этап, сколько обращений, сколько подписанных договоров,
  дата последнего мероприятия. Поиск по имени/телефону/e-mail. Клик → самый «дальний» лид.
- **Отдельной таблицы клиентов нет** — это вычисляемый взгляд на лиды.
- С 2026-11-18 пункт убран из меню (решение 049), страница доступна по адресу.

**Не путать** с «Klienci» в кабинете агентства (`agency_clients`, `/agencja/klienci/…`) — это
другая сущность (см. раздел 8).

## 4. Umowy — договоры

**Файлы:** `app/(app)/umowy/page.tsx`, `contracts_list` (`0030`), генерация
`app/(app)/leady/[id]/umowa/page.tsx`, `lib/documents/service.ts` (`generateContract`),
`lib/documents/barowo/contract.ts`. Модуль `documents`.

**Назначение [Факт]:** реестр подписанных договоров — строка на каждый лид на этапе `won`.

- Поиск: имя, телефон, **номер договора** (последний документ `contract` у лида).
- Строка: номер договора, клиент, «дата · тип · город» мероприятия, сумма платежей по лиду и
  «zapłacono X» (зелёным, если оплачено полностью). Клик → карточка лида.
- **Создание/редактирование договора** — не на этом экране, а из карточки лида
  («Generuj → Umowa»): форма (дата, город, гости, часы, клиент, адрес, цена) → DOCX по шаблону
  (свой шаблон фирмы из «Szablony» или встроенный) + PDF (LibreOffice) → документ с номером
  (`document_counters`), синхронизация полей лида, план платежей, этап → `contract_sent`.
- Повторная генерация создаёт новую версию документа; редактирования готового документа нет.

**Бизнес-правила [Факт]:** дата мероприятия не в прошлом; цена ≥ суммы предоплат;
срок второй предоплаты — 7 дней до события (не раньше завтра); доп. час 600 zł,
штраф 1500 zł (`BAROWO_CONTRACT`); предоплаты — из плана бизнеса (`payment_plan`, решение 049).

**Пробелы / противоречия:** договор попадает в «Umowy» только когда этап стал `won`
(«Umowa podpisana»/«Zadatek wpłacony»), а генерация ставит лишь `contract_sent` — перевод в
«подписан» ручной. Нет статусов документа (подписан/отправлен) кроме поля `status` в
`documents` — **Неизвестно — требуется уточнение**, где оно меняется. Генератор работает только
для движка `barowo`.

## 5. Kalendarz — календарь мероприятий

**Файлы:** `app/(app)/kalendarz/page.tsx`, `components/calendar/agenda.tsx`,
`calendar_events` (`0017`). Модуль `calendar`.

**Назначение [Факт]:** занятость дат мероприятиями.

- Вид — **список дат (agenda), сгруппированный по месяцам**, не сетка (решение 034); отдельного
  «режима сетки» в текущем коде нет. **[Факт]** На странице вкладки «Lista · Kalendarz» ведут
  в список лидов / календарь, а не переключают вид календаря.
- Период: от сегодня на 13 месяцев вперёд; кнопка «Pokaż minione» добавляет 12 месяцев назад.
- Событие = лид с `event_date`, этап не `lost`: **подтверждённое** (`won`, зелёный) или
  **предварительное** (`open`, «Wstępnie»). Показывает клиента, тип мероприятия, город;
  `venue` **не** выводится в `calendar_events`.
- Клик → карточка лида. Легенда цветов.

**Пробелы:** нет создания события из календаря (только через лид), нет времени начала,
нескольких событий у одного лида, фильтра по ответственному.

## 6. Poczta — рассылки

**Файлы:** `app/(app)/poczta/page.tsx`, `components/mailing/panel.tsx`, `lib/mailing/*`,
`lib/mail/*`, миграции `0028`, `0031`. Модуль `documents`. Настройки ящика —
`/ustawienia/poczta`.

**Назначение [Факт]:** массовые письма клиентам (свободные даты, новости, благодарности);
порядок экрана «кому → что → как выглядит → отправить» (решение 037).

**Получатели:** лиды с e-mail, одна строка на адрес (последнее обращение). Поиск по
имени/e-mail/событию. Фильтры: «Z umową», «Bez umowy», «Wydarzenie minęło»,
«Wydarzenie przed nami», «Ostatnie 90 dni», «Tylko za zgodą». «Zaznacz/Odznacz widocznych»,
«Wyczyść wybór», счётчик «Wybrano N z M». Отписавшиеся видны с пометкой, выбрать нельзя.
`?lead=<id>` — получатель выбран заранее (из карточки лида).

**Письмо:** шаблон (выбор / «Zapisz jako szablon», `mailing_templates`), заголовок в две строки,
тема, текст (пустая строка — новый абзац), **переменная `{imie}`** (первое слово имени —
единственная переменная персонализации), кнопка (текст + адрес). Предпросмотр HTML.
В каждом письме — ссылка «Wypisz się».

**Отправка:** «Wyślij test do siebie»; «Wyślij do N» с подтверждением (тема, число, дневной лимит).
Очередь по дням: минутный воркер шлёт столько, сколько позволяет дневной лимит ящика;
крупная кампания идёт несколько дней. Письма по одному. «Ostatnie kampanie»: wysłano /
w kolejce / błędy / zakończona.

**Правила [Факт]:**
- Отписавшиеся исключаются в SQL (`mailing_start`), обойти из интерфейса нельзя.
- Отписка — по нажатию кнопки на `/wypisz` (не по открытию ссылки), токен — подпись адреса
  ключом `MAIL_SECRET_KEY`.
- Согласие на маркетинг (`leads.marketing_consent_at`) хранится отдельно от согласия на ответ.

**Настройки ящика (`/ustawienia/poczta`):** транспорт «Wyłączone / SMTP (Gmail и др.) / Resend»,
имя отправителя, адреса, пароль приложения (зашифрован), сервер/порт, reply-to,
дневной лимит, тестовое письмо. Только owner/admin.

**Пробелы:** **[Факт]** `marketing_consent_at` нигде в коде не заполняется → фильтр
«Tylko za zgodą» всегда пуст. Отправка документов (оферта/договор) клиенту по e-mail из CRM
не реализована (типы `document`, `auto_offer`, `follow_up`, `review` зарезервированы в
`lib/mail/service.ts`, вызовов нет). Нет индивидуальной переписки/входящих.

## 7. Reklama — рекламная аналитика

**Файлы:** `app/(app)/reklama/page.tsx`, `components/ads/forms.tsx`, `lib/ads/*`,
миграция `0037` (`ad_accounts`, `ad_spend`, `ads_report`). Решение 046. Виден всем бизнесам.

**Назначение [Факт]:** расходы на рекламу против заявок CRM: сколько стоит заявка и клиент.

- **Период:** месяц, переключатель «‹ Ten miesiąc ›» (`?m=YYYY-MM`). Других интервалов нет.
- **KPI:** Wydano, Kliknięcia, Zapytania z reklamy, Koszt zapytania, Koszt klienta.
- **Таблица кампаний:** платформа, кампания, расход, клики, запросы (CRM / платформа),
  клиенты, стоимость запроса/клиента. Подсказка о `utm_campaign`; число «несопоставленных» заявок.
- **Konta reklamowe:** список аккаунтов (Meta/Google/ручной) со статусом «Zsynchronizowane …»,
  «Czeka na podłączenie API», «Błąd: …», «Wstrzymane»; пауза/удаление; добавление
  (платформа + ID + название); «Pobierz teraz» (13 месяцев истории, раз в 5 минут).
- **Wydatki ręczne:** кампания (= `utm_campaign`), месяц, сумма, клики → строка на 1-е число месяца
  в отдельном «ручном» аккаунте бизнеса.

**Правила [Факт]:**
- Один бизнес — свои аккаунты; агентство управляет через Meta Business Manager / Google MCC.
- Синхронизация: при ежедневном запуске воркера, аккаунты старше 20 ч, последние 30 дней;
  ошибка пишется в `last_error`. Включается сама при наличии ключей
  (`META_ACCESS_TOKEN`; `GOOGLE_ADS_*`). Meta подключена и работает (Barowo); Google — без ключей.
- Сопоставление: `leads.utm->>'campaign'` = имя **или** ID кампании (без регистра);
  клиент = лид на этапе `won`. Заявки считаются по дате создания лида в выбранном месяце.
- Добавлять аккаунты и расходы — только owner/admin; смотреть — все участники.

**Пробелы:** валюта аккаунта не конвертируется (считается как PLN); нет графиков по дням,
нет выбора произвольного периода; в кабинете агентства существует **вторая, старая модель**
рекламных аккаунтов клиента (`agency_ad_accounts`, блок «Budżet reklamowy» в карточке клиента
агентства — «import statystyk jeszcze nie działa»), не связанная с `ad_accounts`.

## 8. Agencja — финансы агентства

> По заданию — только документирование текущей логики, без новой архитектуры.

**Файлы:** `app/(app)/agencja/*`, `components/agency/*`, `lib/agency/*`, миграции `0020`,
`0023–0027`, `0033–0034`; правила — `docs/agency-distribution.md`. Только кабинет `agency`.

**Назначение [Факт]:** «сколько заработали, кому сколько положено, что осталось настроить у клиентов».

### 8.1 Обзор за месяц (`/agencja?m=`)
- KPI: **Wystawiono** (выставлено), **Otrzymano** (получено), **Oczekiwane** (ожидается),
  **Po terminie** (просрочено); строка «Budżety reklamowe klientów (poza podziałem)».
- «Nowe zlecenie», «Nowy klient», «Powtórz abonamenty z poprzedniego miesiąca» (черновики
  копий абонементов, защита от дублей `repeated_from`).
- **«Kto ile dostaje w tym miesiącu»** — таблица по людям: за продажу, за работу,
  костs/логистика, итого, выплачено («Wypłać»); строки «Fundusz OWO Ads (25 %)» (с округлениями),
  «Nierozdzielone» (нет продавца/исполнителей), «Koszty zewnętrzne»; итог = «Otrzymano»
  (иначе предупреждение «to błąd»).
- **«Fundusz wspólny OWO Ads»** — пришло/потрачено за месяц, сальдо за всё время;
  расходы фонда с категориями (Reklama OWO Ads, Sprzęt, Subskrypcje, Transport, Inne);
  вклады партнёров (например, Artem 7 500 zł) увеличивают сальдо.
- **«Skąd przyszły pieniądze»** — доход по источнику лида клиента.
- **Klienci** агентства — статус, «W tym miesiącu», конфигурация CRM «X z Y», последняя активность.
- **«Wymaga uwagi»** — просроченные оплаты, клиенты просят модули, активные клиенты без заказов
  в месяце, настройка дольше 14 дней.

### 8.2 Сущности и статусы [Факт]
| Сущность | Таблица | Статусы / поля |
|---|---|---|
| Клиент агентства | `agency_clients` | `lead` (Potencjalny) · `active` · `paused` · `lost`; NIP, контакт, город, `client_org_id` (его CRM), `lead_id` (из какого лида) |
| Заказ (Zlecenie) | `agency_orders` | `draft` · `invoiced` · `paid` · `cancelled`; вид `retainer` (Abonament) / `project` (Projekt); сумма netto, `period_month`, `due_date`, `paid_at`, `ad_budget_grosze`, `service_id` |
| Продавцы | `agency_order_sellers` | доли 10 % (сумма ≤ 100 %) |
| Исполнители | `agency_order_work` | % участия в 65 % (колонка `hours` хранит процент, решение 026) |
| Прямые расходы | `agency_order_costs` | строки «за что / сумма / кому» (внешне или партнёру) |
| Фонд | `agency_fund_expenses`, `agency_fund_contributions` | расходы и вклады |
| Выплаты | `agency_payouts` | по месяцу и человеку |
| Чек-лист настройки | `agency_setup_steps/marks` | 12 шагов (организация создана, сервисный доступ, брендинг, воронка, канал, форма, шаблоны, уведомления, приглашение владельца, вход владельца, обучение, абонемент оплачен); часть — автоматически по фактам в базе |

### 8.3 Модель распределения [Факт]
- База = сумма заказа − прямые расходы. **Рекламный бюджет клиента не входит никогда.**
- 10 % — продавцам по долям; 25 % — общий фонд + остатки округления; 65 % — исполнителям
  по процентам. Если у заказа есть услуга — 65 % целиком ответственному за услугу (решение 027).
- Доли — колонки организации `agency_share_*_bp` (по умолчанию 1000/2500/6500), формула в SQL
  `agency_order_split` и её копия в `lib/agency/split.ts` (сверяются тестом).
- Раздел месяца считается по заказам, **оплаченным** в месяце.
- Оплата абонемента CRM в Stripe (`invoice.paid`) автоматически создаёт оплаченный заказ услуги
  «CRM (abonament)»; комиссия Stripe — прямой расход.
- Налоги и ZUS не считаются.

### 8.4 Карточка клиента агентства (`/agencja/klienci/[id]`)
Данные и контакт, «Edytuj dane»; CRM клиента («Otwórz CRM klienta» / «Utwórz CRM klienta» /
«Powiąż z istniejącym biznesem»); чек-лист; **услуги клиента** (`agency_client_services`,
для услуги «Reklama» — месячный бюджет); «Budżet reklamowy» (старые `agency_ad_accounts`);
заказы со статусами («Wystawiono / Opłacono / Anuluj»); история; абонемент модулей и ссылка
оплаты Stripe Checkout.

**Подписки и повторение [Факт]:** абонемент = отдельный заказ на каждый месяц; повтор —
кнопкой «Powtórz abonamenty…» (черновики) или автоматически из Stripe (для CRM).

**Пробелы:** см. открытые вопросы (двойная модель «клиента», связь с `lead_payments`,
фактуры KSeF вне системы).

## 9. Usługi — услуги агентства

**Файлы:** `app/(app)/agencja/uslugi/page.tsx`, `components/agency/services-ui.tsx`,
`lib/agency/services.ts`, миграции `0025`, `0027`, `0033`, `0034`.

**Текущее состояние [Факт]:**
- Таблица `agency_services`: `name`, `description` (до 500 символов, **в интерфейсе не выводится —
  требуется уточнение**), `owner_id` (один ответственный, получает 65 %), `kind`
  (`project` = Projekt / `retainer` = Abonament), `active`, `system_key`.
- **Встроенные услуги** (`system_key`): `crm` — «CRM (abonament)» (оплаты Stripe попадают сюда),
  `ads` — «Reklama» (с месячным бюджетом клиента вне раздела). Их нельзя удалить и переименовать —
  меняется только ответственный и активность.
- **Свои услуги** — добавить/редактировать (название, ответственный, вид расчёта, активность).
  Цен у услуг **нет** (решение владельца 12.11, миграция `0027` удалила цены) — цена живёт в заказе.
- «Katalog startowy»: 5 направлений из `docs/owo-services.md` (Social media i content,
  Reklama Meta i Google, Lokalne SEO i opinie, Strony internetowe, Automatyzacja) + CRM.
- Вклады партнёров в фонд — тоже на этой вкладке.

**Связи [Факт]:** услуга → услуги клиента (`agency_client_services`) → «Utwórz zlecenie»
подставляет услугу и ответственного → заказ (`agency_orders.service_id`) → строка исполнителя
«ответственный, 100 %» ставится базой → 65 % ответственному. Услуги лида агентства
(`agency_lead_services`) переносятся в услуги клиента при превращении лида в клиента.

**Для будущего каталога (не реализовано):** категории, иконки, несколько исполнителей,
цены/индивидуальные цены, карточки с описанием — **отсутствуют**.

## 12. Statystyka — финансовая статистика

**Файлы:** `app/(app)/statystyka/page.tsx` (`/finanse` перенаправляет сюда),
`lib/finance/summary.ts`, SQL `finance_summary` (`0018`). Модуль `payments`.

**Назначение [Факт]:** деньги по платежам лидов (`lead_payments`) — для кабинета клиента
(в т.ч. Barowo); к финансам агентства **не относится**.

- Месяц со стрелками (`?m=`).
- KPI: **Wpłynęło w miesiącu** (`paid_at` в месяце), **Oczekiwane** (не оплачено, срок в месяце),
  **Wartość umów** (`signed_grosze` = сумма **всех** платежей по всем не-проигрышным лидам,
  **без фильтра по месяцу** — **[Факт]**, требует уточнения смысла).
- «Skąd przychodzą pieniądze»: по источнику лида — лиды, оплачено, открыто.
- «Ostatnie miesiące»: поступления по месяцам за 6 месяцев.
- SQL также отдаёт `overdue` / `upcoming` (до 20) и `funnel` (лиды по этапам) —
  **[Факт]** на экране «Statystyka» они не выводятся (просрочки видны только как напоминания
  и в карточке лида); требует решения при редизайне.

**Количество лидов** выводится только в разрезе источников (лиды с платежами).
