| № | Решение | Альтернативы | Плюсы | Минусы / последствия |
|---|---|---|---|---|
| **D-01** | Одна установка, одна БД, изоляция `organization_id` + RLS (как сейчас) | БД на клиента; схема на клиента | Сохраняется весь код и тесты RLS; одна миграция для всех; дёшево | Ошибка в RLS затрагивает всех → обязательные RLS-тесты на каждую таблицу |
| **D-02** | Связь «агентство ↔ организация» — явная таблица `platform_managed_orgs` с типом `service`/`client`; автосвязь `linkBusinessesToAgency` выключается | Оставить автосвязь | Barowo может быть «обслуживаемой», но не «клиентом агентства» — по заданию | **Требует решения:** сейчас Barowo в коде — клиент агентства (абонемент → заказы агентства). Нужно определить relation для Barowo и что делать с уже созданными заказами |
| **D-03** | Слои Platform Core / CRM Core / Config Engine / Templates / Modules / Agency — каталоги `lib/platform`, `lib/crm`, `modules/<key>` | Микросервисы | Один деплой, маленькая команда | Нужна дисциплина импортов → правило eslint `no-restricted-imports` между слоями |
| **D-04** | Динамические данные: гибрид — `records` + типизированные `record_values` + `record_links`; стандартные и денежные сущности — таблицы | Таблица на сущность (DDL из админки); чистый JSONB | Типизация, индексы без DDL, одна RLS, FK по organization_id | Запросы через генератор; при росте сущность модуля переводится в свою таблицу |
| **D-05** | Критерий «таблица или records»: деньги, массовые отчёты, юридическая значимость → таблица | Всё в records | Финансы остаются строгими | Решение для каждой новой сущности осознанно |
| **D-06** | UI только из реестра компонентов + валидированный JSON; ни SQL, ни JS из БД | Пользовательский код/JSX | Безопасность | Сложные экраны — кодом модуля |
| **D-07** | Конфигурацию меняет только `platform_staff` (architect); клиент — пользователь | Клиентский конструктор | Целостность, поддерживаемость | Каждое изменение клиента — через OWO |
| **D-08** | Воркер — отдельный процесс того же образа + advisory-lock | Оставить в веб-процессе | Нет двойного исполнения при масштабировании, веб не тормозит | Ещё один сервис Railway (≈+5 $/мес) |
| **D-09** | Три независимых денежных контура: `payments` клиентов, `agency_*`, подписки платформы | Общая «финансовая» сущность | Нет смешения денег клиента и агентства | Сводные отчёты — только явными связями (billing_events → заказ crm) |
| **D-10** | Фильтры по связям — глубина пути ≤ 2 | Произвольная | Предсказуемая производительность | Сложные отчёты — кодом модуля |
| **D-11** | Обобщение `lead_payments` → `payments`: сначала новая таблица + view совместимости `lead_payments` | Новая таблица как view над старой | Новые модули сразу пишут в общую таблицу | Нужны `instead of` триггеры и проверка SQL-функций |
| **D-12** | Одна модель рекламы (`ad_accounts`/`ad_spend` модуля `ads_analytics`); `agency_ad_accounts` переносится и удаляется | Оставить обе | Нет дублей | Нужно решение владельца по бюджетам клиентов в агентстве |
| **D-13** | Шаблоны версионируются, обновление в организацию — вручную трёхсторонним слиянием | Автообновление | Не ломает индивидуальные настройки | Работа OWO при каждом обновлении шаблона |

## Открытые вопросы (нужен ответ владельца)
1. **D-02:** Barowo — клиент агентства (платит, заказы в финансах агентства) или только
   обслуживаемая организация? Что делать с прошлыми заказами «CRM (abonament)» Barowo?
2. Отдельный сервис воркера на Railway — согласовать стоимость.
3. Нужен ли клиентам хоть какой-то самостоятельный уровень настройки (например, свои шаблоны
   писем, названия этапов) — или всё строго через OWO?
4. Будет ли более одного кабинета-агентства (партнёры/франшиза)? Влияет на `platform_managed_orgs`.
5. Пилотная отрасль после Barowo — автосервис? Есть ли реальный клиент для проверки?
6. Языки: только польский или нужна мультиязычность конфигурации (в спецификации заложено `{"pl":…}`)?
7. Хранение файлов: [Факт] сейчас содержимое в БД (`bytea`, `lead_attachments`, `organization_templates`, `0032`). При росте — S3-совместимое хранилище (Railway bucket); нужно решение по сроку.

## Ответы владельца (2026-11-18)
- **D-02 — утверждено:** Barowo — собственная фирма Ивана, **не клиент агентства**. Связь OWO ↔ Barowo —
  только `relation = 'service'` (сервисный доступ команды), без заказов «CRM (abonament)» и без учёта
  в финансах агентства. Автосвязь `linkBusinessesToAgency` подлежит отключению (этап M1);
  уже созданную запись Barowo в `agency_clients` и её заказы — проверить и убрать отдельной задачей.
- **D-07 — утверждено:** клиенты почти ничего не настраивают; конфигурацию делает OWO (Nikon вместе с Claude).
  Админка конфигурации — внутренний инструмент, без полировки для клиентов.
- **Пилот:** реальный клиент есть (знакомые); отрасль — уточнить. Трафика пока нет → требования к
  производительности умеренные, приоритет — скорость запуска новых CRM.
- **Язык — только польский:** в конфигурации подписи хранятся простыми строками, без `{"pl": …}`.
- **D-08 (отдельный воркер) — ждёт решения.**

## Пилот №2: посредник по рефинансированию ипотеки (2026-11-18)
Клиент — риелтор/кредитный посредник, сотрудничает с банками: предлагает владельцам ипотеки
перейти на более выгодный кредит, банк платит ему комиссию (%). Трафик: Meta + сайт; нужна
аналитика Google Ads (код синхронизации готов, нужны ключи — решение 046).

Черновик шаблона `mortgage_refi@1` (уточнить с клиентом):
- **Сущности:** Contact (ядро) · Lead (ядро, канал/utm) · **Kredyt obecny** (records: банк, остаток, ставка,
  тип ставки, срок, платёж, LTV) · **Wniosek** (records: банк-партнёр, сумма, новая ставка, статус банка) ·
  **Bank partnerski** (records-справочник: комиссия %).
- **Процесс Wniosek:** Nowy lead → Analiza kredytu → Oferta porównawcza → Dokumenty → Złożony w banku →
  Decyzja → Umowa podpisana (won) → Prowizja wypłacona (won, tag `commission_paid`); Odrzucony (lost).
- **Деньги посредника:** ожидаемая комиссия = сумма кредита × % банка; поступление — `payments`
  (контур 1, его выручка), не путать с финансами агентства.
- **Автоматизации:** новый лид → задача «Zadzwoń 15 min»; нет документов 3 дня → напоминание клиенту;
  окончание фиксированной ставки (дата) → повторный контакт.
- **Чувствительные данные:** финансовые данные клиентов → права на поля, журнал доступа;
  требования RODO и регулирование посредников кредитных (KNF) — уточнить у клиента.
