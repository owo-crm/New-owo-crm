# 09 — Перенос с Apps Script (бот v39) на веб-CRM

## Текущее состояние (на 12.10.2026)

- Код: `BAROWO site/crm-system/apps-script/` (git, ветка `codex/crm-offer-client-actions`, `d4a46df`; поверх — патч `handoff/crm-v39-claude.patch`).
- Работает: Apps Script **v39**, два развёртывания, база — Google Sheets (`Leads`, `Contacts`, `Logs`, `Documents`, а также старые `Lidy`, `Kontakty`, `Finanse`, `Spam`).
- Сайт barowo.com отправляет форму на Apps Script Web App (`doPost`).
- Документы: шаблоны в Google Docs (ID в Script Properties), папка на Google Drive.

**Правило: старый Apps Script не трогаем и не выключаем, пока новый CRM не прошёл паритет и 2 недели параллельной работы.**

## Стратегия: «рядом, потом переключить»

1. **Строим новое рядом.** Barowo — тенант №1 в новом CRM.
2. **Импорт истории.** Скрипт `scripts/import-apps-script.ts`: читает экспорт CSV листов `Leads`, `Contacts`, `Documents` → `leads`, `lead_events`, `documents` (файлы — ссылками на Drive, без копирования). `legacy_uid` сохраняем. Импорт повторяемый (upsert по `legacy_uid`).
3. **Двойная отправка формы.** На сайте форма шлёт в Apps Script (как сейчас) **и** в `/api/intake/<barowo-key>`. Отдельная ветка сайта, деплой только с согласия Ивана.
4. **Новый бот уведомлений.** Новый CRM использует отдельного Telegram-бота, чтобы не конфликтовать с webhook старого.
5. **2 недели сравнения:** все лиды есть в обоих местах? уведомления быстрее? Оферты/договоры генерируются?
6. **Переключение:** форма шлёт только в новый CRM; старый бот — только чтение; Sheets — архив на 3 месяца.

## Готово: 1.13a — импорт Leads CSV

Скрипт сначала делает dry-run без ключей. Читает только файлы **внутри crm-web** (проверяются и symlink), поддерживает BOM, кавычки/переносы, запятую/точку с запятой, явную карту колонок. UID, имя, контакт, этап и original created_at обязательны; неизвестные этапы/некорректные даты/повтор UID выдаются как ошибки строк. created_at и first_response_at — ISO с часовым поясом, без догадок. Бюджет — колонка budget в zł или budget_grosze в грошах.

Проверяются все строки до первого обращения к базе. Если есть ошибки, apply не начинается. Обычный повтор не перезаписывает правки CRM: существующий legacy_uid пропускается. Вставка одной строки/истории атомарна, поэтому после ошибки базы импорт безопасно повторить. Начальные уведомления и напоминания об импортированной истории исключены. Известный этап контакта скрывает бон ожидания, но неизвестное время реакции не подменяется датой импорта.

Настоящий CSV пока не предоставлен. **1.13b остаётся открытой:** проверить реальные заголовки/форматы, сопоставить поля, сверить количество и только затем сделать перенос в staging. Старый Apps Script и его файлы не читались/не менялись. Contacts/Documents в этой версии не записываются: документальная схема появляется в этапе 2; ссылки на Drive переносим после неё.
