Почему не Vercel: бесплатный план Hobby только для некоммерческого использования.
Почему не Netlify: на бесплатном плане при исчерпании кредитов ставятся на паузу **все** сайты аккаунта — риск выключить barowo.com.
Почему приём лидов в Supabase Edge Function: Cloud Run засыпает без запросов и просыпается несколько секунд; заявки и уведомления должны работать мгновенно независимо от этого.
Риски бесплатного режима: нет автобэкапов (делаем свой ночной `pg_dump`), лимиты Resend. Проверять лимиты на страницах цен перед запуском — они меняются.

**012 · 2026-10-12 · Связи лидов проверяются внутри фирмы, история дописывается.**
Составные внешние ключи включают `organization_id`: RLS защищает доступ, а FK не даёт серверу случайно соединить разные фирмы. Номер лида — глобальная PostgreSQL identity (пропуски допустимы), отдельный счётчик не нужен. `lead_events` и `intake_log` неизменяемы для пользователей; исправления записываются новыми событиями. Поля с ключами фирмы и источника не обновляются из клиента.

**013 · 2026-10-12 · Лимит формы хранится в PostgreSQL; в журнале нет содержимого заявки.**
Используем уже существующий `intake_log` и транзакционную блокировку для 10 попыток/час/IP/фирму; локальная память Edge не подходит при нескольких запусках. IP хранится как HMAC с отдельным серверным секретом. Веб-форма обращается напрямую к Edge URL (009), не через засыпающий Next/Cloud Run. Общая TypeScript-логика импортируется Deno с `.ts` и per-function `deno.json` (официальная рекомендация Supabase). Минимальный Node обновлён до 22.12 — это требование текущих Supabase/Vitest.

**014 · 2026-10-13 · Durable outbox и явное включение отправок.**
Доставки создаются триггером внутри транзакции лида; Edge/Next только будят worker, поэтому сбой запроса не теряет уведомление. Lease + SKIP LOCKED исключают параллельную отправку одной задачи; retry до 5 попыток. Ключ включает kind для первого уведомления и напоминаний. Интеграции защищены OUTBOUND_NOTIFICATIONS_ENABLED (по умолчанию выключено), cron требует отдельный секрет. Клиент не получает серверных ключей. Cron — ручной SQL-черновик, не миграция с внешними побочными эффектами. Telegram даёт at-least-once при редком сбое между API и записью результата; у Resend есть provider idempotency, у Push — tag.

**015 · 2026-10-13 · Импорт истории сначала проверяет файл и не перезаписывает CRM.**
Dry-run — режим по умолчанию, apply — отдельный явный флаг. legacy_uid получает namespace apps-script; повтор пропускает существующую запись, чтобы экспорт старой системы не затёр новые правки. История импортируется тихо, без outbox/напоминаний. Время ответа не выдумывается: известный этап контакта и измеренная длительность реакции — разные сведения. Реальный перенос требует CSV и staging, он выделен в 1.13b.

**016 · 2026-10-13 · Ссылки на удалённого участника обнуляются внутри фирмы.**
Составной FK остаётся защитой между фирмами, но ON DELETE SET NULL применяется только к assigned_to/actor_user_id, чтобы не блокировать снятие сотрудника и не удалять лиды/историю. organization_id сохраняется. Возможность точечного SET NULL сверена с [PostgreSQL](https://www.postgresql.org/docs/16/ddl-constraints.html) и проверена PGlite, в том числе для сотрудника двух фирм.

**017 · 2026-11-10 · Монолит: Next.js + Postgres на Railway, без Supabase и без Google. (Заменяет хостинг/БД из 003 и 009.)**
Решение Ивана: никаких Apps Script/Google Sheets; код на GitHub, деплой на Railway.
- **Один сервис** Next.js: интерфейс, server actions, `/api/intake/<key>` (форма сайта), `/api/telegram` (вебхук), `/api/live` (SSE), `/api/health`. Фоновый воркер уведомлений — `instrumentation.ts`, раз в минуту в том же процессе (вместо pg_cron + Edge Functions). Railway: ровно 1 реплика.
- **База:** Railway Postgres 16. SQL-миграции прототипа сохранены без изменений (`db/migrations/`); `0000_platform.sql` создаёт роли `anon/authenticated/service_role`, схему `auth`, `auth.uid()`. Приложение на запрос пользователя делает `set local role authenticated` + id в `request.jwt.claim.sub` → **RLS-политики работают как в Supabase** (защита, даже если в коде забыт фильтр по фирме). Серверные задачи — владелец базы.
- **Логины свои:** scrypt (Node crypto), сессия = случайный токен в httpOnly-cookie, в базе только SHA-256. Сброс пароля одноразовой ссылкой (1 ч), письмо через Resend. Регистрация закрыта по умолчанию (`REGISTRATION_OPEN`), аккаунты создаёт Owo Ads скриптом `npm run user:create`.
- **Realtime:** триггер `pg_notify('lead_changes')` → один LISTEN на процесс → SSE в браузер.
- **Идемпотентность заявок:** `submission_id` (поле формы или заголовок `Idempotency-Key`) → `ingest_lead_once`, повтор не создаёт второй лид.
- Мультиарендность сохраняется: Barowo — первая фирма; клиенты Owo Ads — свои фирмы; переключатель фирм — cookie `owo_org`.
Отвергли: Drizzle/Prisma (переписывать проверенный SQL ради ORM — риск без выгоды); отдельный воркер-сервис (лишний сервис и деньги на старте); Supabase (не монолит).

**022 · 2026-11-11 · Подписка по модулям, оплата через Stripe.**
- Цена = база «Leady» 39 zł + модули: Dodatkowe kanały 29, Oferty i umowy 59, Płatności 29, Kalendarz 19 (netto/мес.); каждый пользователь сверх включённого +15 zł; все модули → «Pakiet Pełny» 149 zł с 3 пользователями (берётся сам, если дешевле). Клиент рекламы: база 0, модули −50 %. Каталог и цены — только `lib/billing/modules.ts`, расчёт — `lib/billing/pricing.ts`.
- Модули хранятся в `organization_modules`; выключенный модуль прячется из меню и показывает экран «Poproś o moduł». Включает только агентство (`set_organization_modules`, проверка `manages_organization`). Новый бизнес стартует со всеми модулями (пробный период); мастер «Utwórz CRM klienta» сразу ставит выбранные.
- Автоматический рост суммы: после смены модулей, скидки, входа или удаления пользователя абонемент пересчитывается и строки подписки Stripe обновляются (`price_data`, продукт `owo_crm_<ключ>`). Рост — `proration_behavior=always_invoice` (доплата за остаток месяца списывается сразу), снижение — `create_prorations` (кредит на следующий счёт).
- Первая оплата — ссылка Stripe Checkout, которую агентство отправляет клиенту само (система ничего не шлёт). Карта, счета, отмена — портал Stripe из «Ustawienia → Abonament».
- Налоги: для польских фирм — своя ставка VAT 23 % (`STRIPE_TAX_RATE_ID`, бесплатно). Stripe Tax (+0,5 % оборота) — только если появятся клиенты за границей (`STRIPE_AUTOMATIC_TAX=true`). Stripe налог не вычитает и не платит: собирает его сверху суммы, отдаёт нам, VAT платим мы сами (JPK).
- Оплата счёта (`invoice.paid`) → строка заказа в кабинете агентства (абонемент, оплачено); комиссия Stripe записывается прямыми расходами, поэтому раздел 10/25/65 считается с реальных денег.
- Счёт Stripe — не польская фактура: с 2026 года фактуры B2B выставляются через KSeF. Фактуры делаем в бухгалтерской программе с интеграцией Stripe→KSeF (например, Fakturownia / inFakt / iFirma), номер счёта Stripe сохраняется в заметке заказа.
- Кабинет OWO Ads создаётся сам при запуске (`ensureAgencyWorkspace`), руками ничего создавать не надо.
Отвергли: Stripe SDK (нужно 6 запросов — свой клиент проще проверить тестами), Stripe Tax по умолчанию (лишние 0,5 % для внутреннего рынка), тарифы-«коробки» вместо модулей.
