# Бэкап базы

Две независимые страховки (решение 033):

1. **Railway** — встроенные бэкапы сервиса Postgres. Включает владелец в интерфейсе Railway.
2. **GitHub Actions** — каждую ночь (`.github/workflows/backup.yml`, ~2–3 ночи по Варшаве):
   `pg_dump` → **проверочное восстановление** в пустой Postgres той же версии → шифрование →
   artifact на 30 дней. Копия лежит у другого поставщика, чем сама база.

Если ночная проверка не нашла в восстановленной базе ни одного лида, задача падает красным —
GitHub пришлёт письмо владельцу репозитория.

## Настройка (один раз, делает Иван)

### 1. Секреты репозитория

GitHub → `owo-crm/new-owo-crm` → Settings → Secrets and variables → Actions → **New repository secret**:

| Имя | Что вставить |
|---|---|
| `BACKUP_DATABASE_URL` | Railway → сервис **Postgres** → Variables → значение `DATABASE_PUBLIC_URL` (внешний адрес; внутренний `DATABASE_URL` из GitHub недоступен) |
| `BACKUP_PASSPHRASE` | длинная случайная фраза, **минимум 20 символов**. Сохрани её в менеджер паролей: без неё копию не расшифровать |

Именно секрет, не переменная: значение не видно в логах и в интерфейсе.

### 2. Первый запуск

GitHub → Actions → **Nightly database backup** → Run workflow. Через 2–3 минуты в итогах задачи
будет таблица: сколько фирм, пользователей, лидов, документов оказалось в восстановленной копии.

### 3. Бэкапы Railway

Railway → сервис Postgres → вкладка **Backups** → включить расписание (Daily). Если вкладки нет
или она недоступна на тарифе — написать об этом в PROGRESS.md: тогда страховка только одна.

### 4. Лишний том

В проекте Railway есть неиспользуемый том `postgres-volume` (регион iad, остаток первой
установки). Открыть, убедиться, что к нему не подключён ни один сервис, удалить.

## Восстановление

Нужны `psql`, `pg_restore` (той же или более новой версии, чем сервер) и `gpg`.

1. GitHub → Actions → нужный ночной запуск → Artifacts → скачать `owo-db-ГГГГ-ММ-ДД`, распаковать zip.
2. Восстановить в **новую пустую базу** (например, новый Postgres в Railway или локальный):
   ```sh
   BACKUP_PASSPHRASE='…' scripts/backup/restore.sh owo-2026-11-13.dump.gpg "postgresql://…/новая_база"
   ```
   Скрипт сам создаст роли (`anon`, `authenticated`, `service_role`), восстановит данные и
   права и покажет сводку. В непустую базу он не пишет.
3. Проверить сводку, затем переключить `DATABASE_URL` приложения на новую базу.

Восстановить **поверх** рабочей базы (только при настоящей аварии, когда рабочая испорчена):
добавить третьим аргументом `--overwrite`. Это удаляет текущие данные.

## Проверено

12.11.2026 на Postgres 16: база со всеми 27 миграциями и лидами с польскими буквами и эмодзи →
`pg_dump` → шифрование → `restore.sh` в пустую базу → данные, RLS и права на месте,
`npm run db:migrate` на восстановленной базе отвечает «Baza aktualna». Отказ записи в непустую
базу и неверная фраза — проверены.
